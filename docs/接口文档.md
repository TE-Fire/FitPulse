# FitPulse 接口文档

> 项目代号：FitPulse  
> 版本：v1.1  
> Base URL：`http://localhost:8080/api/v1`  
> JDK：21 · 后端：Spring Boot 3.2.5 · 数据库：MySQL 8

> 本文档仅包含**已开发或本次计划开发**的接口，未实现模块（看板/训练/健康/AI）暂未列入，待对应模块开发时补充。

---

## 一、基础约定

### 1.1 统一返回结构 `Result<T>`

所有接口响应均包裹在以下结构：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { "..." },
  "timestamp": 1700000000000
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | Integer | 业务状态码，200=成功，非200=异常 |
| message | String | 描述信息 |
| data | T / null | 业务数据（data=null 的接口也会返回该字段） |
| timestamp | Long | 服务端毫秒时间戳 |

### 1.2 状态码 `ResultCode`

| code | 含义 | 典型场景 |
|---|---|---|
| 200 | 操作成功 | 正常返回 |
| 400 | 参数错误 | 必填缺失、格式不合法、长度越界 |
| 401 | 未登录 / Token 无效 | 未带 Authorization、Token 过期、签名错 |
| 403 | 无权限 | 非本人数据、角色越权 |
| 404 | 资源不存在 | ID 查不到、路径无效、邮箱未注册 |
| 409 | 业务冲突 | 用户名/邮箱重复、目标状态冲突、发码防刷 |
| 500 | 服务端异常 | 兜底未捕获错误 |

### 1.3 鉴权

- **免鉴权接口**：`POST /auth/register/send-code`、`POST /auth/register`、`POST /auth/login/send-code`、`POST /auth/login`、`POST /auth/refresh`、`POST /auth/forgot-password/send-code`、`POST /auth/forgot-password/reset`
- **其他所有接口**：请求头
  ```
  Authorization: Bearer <accessToken>
  ```
- Token 类型：JWT HS256
- 有效载荷 Claim：`sub=userId`、`username`、`iat`、`exp`
- accessToken：默认 24h
- refreshToken：默认 30d（存 Redis，注销可主动失效）
- 401 处理：前端调 `/auth/refresh` 换一对新 Token；refresh 失败 → 清空本地凭证 → 跳转登录页

## 二、认证模块 `/auth`

> 注册流程与登录流程对称：都需先发码→再带 code 完成业务。**注册验证码与登录验证码在 Redis key 前缀上完全隔离**，不可互用。

### 2.1 发送注册验证码 POST `/auth/register/send-code`
鉴权：否

**请求体**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| email | String | 是 | 必须以 `@qq.com` 结尾 | 接收注册验证码的 QQ 邮箱 |

```json
{ "email": "fire_dev@qq.com" }
```

**成功响应** `data` 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| code | String | **6 位注册验证码明文**，与控制台 `log.info("[注册验证码] ...")` 输出、邮件正文、Redis 存储值完全一致，本地/演示无需查控制台即可联调 |
| expireMinutes | Number | 验证码有效期（分钟），目前固定 5 |
| rateLimitSeconds | Number | 同邮箱发送频率限制（秒），超过此间隔前重复发送会返回 409 防刷，目前固定 60 |

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { "code": "482917", "expireMinutes": 5, "rateLimitSeconds": 60 },
  "timestamp": 1755410000000
}
```

> 服务端行为：
> 1. 若该邮箱**已注册**，直接返回 409（邮箱已注册），不发码
> 2. 60 秒内重复发送返回 409（防刷）
> 3. 生成 6 位数字验证码
> 4. 存入 Redis（key=`fitpulse:register:code:{email}`，TTL=5min，**与登录验证码前缀独立**）
> 5. **日志 INFO 打印**验证码（开发调试）
> 6. 通过 QQ 邮箱 SMTP 发送，邮件主题"FitPulse 注册验证码"
> 7. 上述 `data.code` 直接**明文回传**=日志=邮件=Redis，方便联调
>
> 常见 409：邮箱已注册 / 发送过于频繁（60s 防刷）；常见 400：邮箱格式不合法

### 2.2 注册 POST `/auth/register`
鉴权：否

**请求体**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| email | String | 是 | 必须以 `@qq.com` 结尾 | QQ 邮箱（唯一） |
| password | String | 是 | 8-64，至少含字母+数字 | 明文密码（服务端 BCrypt 存储） |
| code | String | 是 | 6 位数字 | **注册验证码**（先调 2.1 发送，5min 内有效） |

```json
{
  "email": "fire_dev@qq.com",
  "password": "Fire@2026",
  "code": "482917"
}
```

**响应**：`data = null`
```json
{ "code": 200, "message": "操作成功", "data": null, "timestamp": 1755410000000 }
```

> 服务端行为：
> 1. 校验注册验证码：空 / 格式 / 过期 / 错误 分别返回 400/400/401/401 精准枚举
> 2. 校验通过后 **立即从 Redis 删除**该验证码（一次性消费，防重放）
> 3. 邮箱唯一检查（409 已注册）
> 4. `username` 由后端自动生成（取邮箱前缀，如 `fire_dev@qq.com` → `fire_dev`，冲突时追加数字后缀）
> 5. 写入 user 表（status=1），不自动登录
>
> 常见 400：注册验证码为空 / 格式不正确；常见 401：注册验证码已过期 / 错误；常见 409：邮箱已注册

---

### 2.3 登录 POST `/auth/login`
鉴权：否

> 合并登录接口：通过 `type` 字段区分密码登录（1）或验证码登录（2）。

**请求体**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| email | String | 是 | 必须以 `@qq.com` 结尾 | QQ 邮箱 |
| type | Integer | 是 | 1 或 2 | **1=密码登录 2=验证码登录** |
| password | String | type=1 时必填 | 8-64，至少含字母+数字 | 密码（仅 type=1 时需要） |
| code | String | type=2 时必填 | 6 位数字 | **登录验证码**（仅 type=2 时需要，先调 2.4 发送，与注册验证码互不相通） |

**type=1 密码登录示例**：
```json
{
  "email": "fire_dev@qq.com",
  "type": 1,
  "password": "Fire@2026"
}
```

**type=2 验证码登录示例**：
```json
{
  "email": "fire_dev@qq.com",
  "type": 2,
  "code": "836291"
}
```

**响应 data = LoginUserVO**

| 字段 | 类型 | 说明 |
|---|---|---|
| accessToken | String | 24h 访问令牌 |
| refreshToken | String | 30d 刷新令牌 |
| userId | Long | 用户 ID |
| username | String | 用户名（注册时由邮箱前缀自动生成） |

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIx...",
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIx...",
    "userId": 1,
    "username": "fire_dev"
  },
  "timestamp": 1755410001000
}
```

> 常见 400：type=1 密码错误（统一提示"邮箱或密码错误"防枚举）；type=2 验证码错误或已过期

### 2.5 刷新 Token POST `/auth/refresh`
鉴权：否（请求体带 refreshToken，不入 Bearer）

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| refreshToken | String | 是 | 登录下发的 refreshToken |

```json

```

**响应**：同 2.3（返回一对新 Token + userId/username）

### 2.8 登出 POST `/auth/logout`
鉴权：是（Bearer accessToken）

**请求**：无 Body，无需参数

**响应**：`data = null`

服务端行为：
1. 从 accessToken 解析 userId
2. Redis 中删除该用户的 refreshToken 缓存
3. 返回成功

## 三、用户模块 `/user`

> 本次开发范围：资料 / 账号 / 密码 / 头像 / 训练统计 / 健康概览。**用户目标（user_goal）功能暂时搁置**，待后续单独开发。

> 设计说明：PC 端与移动端后端**合并为单一 user 模块**，不做 user/admin 分拆，符合"单账号个人使用"设计。

### 3.4 修改密码 PUT `/user/password`
鉴权：是

**请求体 = ChangePasswordReq**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| oldPassword | String | 是 | 当前密码明文 | 旧密码（服务端 BCrypt 比对） |
| newPassword | String | 是 | 8-64，至少含字母+数字 | 新密码（BCrypt 加密存储） |
| confirmPassword | String | 是 | 必须与 newPassword 一致 | 确认新密码 |

```json
{
  "oldPassword": "Fire@2026",
  "newPassword": "Fire@2027",
  "confirmPassword": "Fire@2027"
}
```

**响应**：`data = null`

> 服务端行为：
> 1. 从 accessToken 解析 userId
> 2. 两次密码不一致返回 400
> 3. 旧密码比对失败返回 401（旧密码错误）
> 4. BCrypt 加密新密码后更新 user.passwordHash
> 5. **不自动失效 Token**（客户端可选择是否重新登录）
>
> 常见 400：两次密码不一致 / 新密码格式不合法；常见 401：旧密码错误

## 四、文件模块 `/file`

> 本次仅实现通用上传接口，支持本地存储降级（个人版无需 MinIO）。

### 4.1 上传文件 POST `/file/upload`
鉴权：是
Content-Type：`multipart/form-data`

**表单字段**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| file | MultipartFile | 是 | ≤10MB；图片=jpg/png/webp/gif | 上传的文件 |
| bucket | String | 是 | `avatar` / `exercise` / `food` / `general` | 存储桶分类 |

**响应 data = FileUploadVO**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 文件资源 ID（供业务表保存关联） |
| fileUrl | String | 可直接访问 URL（本地降级=/files/<bucket>/...） |

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": 1873487291038476300,
    "fileUrl": "/files/avatar/20260819/abc123.jpg"
  },
  "timestamp": 1755410000000
}
```

> 服务端行为：
> 1. 从 accessToken 解析 userId
> 2. 校验文件大小与格式
> 3. 调用 FileStorageService 存储文件
>    - 本地模式：写入 `${fitpulse.upload.path}/<bucket>/<yyyyMMdd>/<uuid>.<ext>`
>    - MinIO 模式：putObject 到指定 bucket（本次暂不实现）
> 4. 写入 file_resource 表
> 5. 返回文件 URL
>
> 常见 400：文件为空 / 文件过大 / 格式不支持
